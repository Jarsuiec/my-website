# WorkControl AI — личный рабочий центр e-commerce

Одно место для всех обращений: Gmail, Allegro, Decathlon, Etsy, UPS/DPD, WhatsApp, возвраты, рекламации, фактуры.
Приложение запоминает всё за вас и показывает, что нужно сделать сейчас.

- **Стек:** Next.js 16 + TypeScript, SQLite (better-sqlite3, полнотекстовый поиск FTS5), Node.js 22.
- **Данные хранятся у вас:** файл `data/workcontrol.db`. Никуда не отправляются, пока вы сами не включите AI.
- **Язык интерфейса:** русский. Письма на польском, английском и немецком отображаются и ищутся корректно (поиск находит «Dąbrowska» и по «dabrowska»).

## 1. Быстрый старт на Windows

1. Установите **Node.js 22 LTS**: https://nodejs.org (кнопка «LTS», всё по умолчанию).
2. Распакуйте ZIP проекта, например в `C:\WorkControl`.
3. Двойной щелчок по **`start-windows.bat`**.
   Первый запуск: установит зависимости и соберёт приложение (несколько минут). Затем откроется браузер на http://127.0.0.1:3000.
4. Для следующих запусков — снова `start-windows.bat` (уже быстро). Окно консоли не закрывайте, пока работаете.

То же вручную (PowerShell в папке проекта):

```powershell
npm ci
copy .env.example .env
npm run build
npm start
```

По умолчанию приложение доступно **только с этого компьютера** (127.0.0.1) и работает без пароля.

### Пароль и доступ с телефона / из сети

Откройте `.env` и задайте:

```
APP_PASSWORD=ваш-надёжный-пароль
HOST=0.0.0.0
```

Без `APP_PASSWORD` приложение откажется запускаться на `0.0.0.0`. Для доступа через интернет обязательно используйте HTTPS (раздел 3).

## 2. Первые шаги

1. **Настройки → Мои адреса** — впишите свои рабочие e-mail (можно домен целиком: `@moj-sklep.pl`) и имя в WhatsApp. Так приложение отличает ваши ответы от писем клиентов.
2. **Загрузить данные** — перетащите файлы или вставьте текст переписки.
3. Откройте **Главную** — там срочные задачи, кто ждёт ответа, возвраты, доставки.

Посмотреть без своих данных: **Настройки → Загрузить демо-данные** (помечены «ДЕМО», удаляются кнопкой «Удалить демо-данные»).
Примеры файлов для импорта — в папке `samples/`.

### Где взять файлы

| Источник | Как выгрузить |
|---|---|
| Gmail, одно письмо | Открыть письмо → ⋮ → «Скачать сообщение» → `.eml` |
| Gmail, всё сразу | https://takeout.google.com → только «Почта» → `.mbox` (включает «Отправленные» — так приложение видит ваши ответы) |
| Allegro / Decathlon / Etsy | Уведомления о сообщениях приходят на почту → импорт писем; или скопируйте переписку в поле «Вставьте текст» |
| WhatsApp | Чат → ⋮ → «Ещё» → «Экспорт чата» → «Без медиафайлов» → `.txt` |
| Таблицы (Apilo, Shopify, свои списки) | CSV / XLSX. Колонки распознаются по названию: `from/email`, `name/klient`, `subject/temat`, `date/data`, `message/treść`, `order/zamówienie`, `source`. Строки с колонкой `title` без текста сообщения импортируются как задачи |
| Много писем | ZIP-архив с `.eml`/`.mbox`/`.txt` внутри |
| PDF | Только если в PDF есть текстовый слой (сканы не читаются — приложение честно сообщит) |

## 3. Сервер, Docker и HTTPS

```bash
cp .env.example .env     # задайте APP_PASSWORD
docker compose up -d --build
```

Приложение будет на `http://127.0.0.1:3000` сервера, данные — в `./data`.

HTTPS с автоматическим сертификатом Let's Encrypt (нужен домен, направленный на сервер, и открытые порты 80/443):

```bash
echo "DOMAIN=work.example.pl" >> .env
docker compose --profile https up -d --build
```

Без Docker (Linux): Node.js 22 → `npm ci && npm run build && npm start`, перед ним любой HTTPS-прокси (Caddy, nginx). Cookie сессии ставится с флагом `Secure`, если прокси передаёт `X-Forwarded-Proto: https`.

## 4. Резервное копирование

- **Архив → Скачать ZIP** — полная копия: `backup.json` (всё для восстановления), CSV задач/сообщений/заметок, отчёт и контекст для Claude. В каждом файле указано время создания.
- **Архив → Сохранить архив на сервере** — копия в `data/backups/`.
- **Автоматически:** раз в день при открытии главной создаётся копия в `data/backups/` (хранятся 14 последних).
- **Восстановление:** Архив → Восстановить из копии → выберите `.zip` или `.json`. Перед заменой текущие данные автоматически сохраняются в `data/backups/workcontrol-before-restore-….json`.
- Перед «Удалить все данные» тоже создаётся копия.
- Копия всей папки: `backup-windows.bat` копирует `data\` в `backups\ДАТА`. Надёжнее всего делать это при закрытом приложении либо полагаться на JSON-копии из `data/backups/`.

В резервную копию не попадают ключи API и пароль (они только в `.env`).

## 5. Что работает сейчас (этапы 1–2)

Всё в этом списке проверено автоматическими тестами (раздел 7).

**Задачи**
- Главная: 7 карточек (срочные, требуют ответа, ожидают клиента, доставка, возвраты, выполнено сегодня, возможно пропущенные), по клику — фильтр.
- Список задач: название, источник, клиент, заказ, описание, дата последнего сообщения, приоритет, статус, следующее действие, дедлайн (только если задан).
- Кнопки: Выполнено / Ответил / Ожидаю / Отложить (на 3 часа, до завтра 8:00, 3 дня, неделя, своё время) / Открыть / Заметка. Отложенная задача сама возвращается в срок.
- Выполненные задачи исчезают из активных и остаются в истории («Все задачи → История»).
- Фильтры: источник, статус, срочность, категория, диапазон дат, текст. Кнопка «Осталось со вчера».
- Ручное создание и редактирование задач, этапы возвратов (запрошен → этикетка → курьер → в пути → на складе → деньги возвращены) и рекламаций.
- История действий по каждой задаче.

**Импорт**
- EML, MBOX, CSV, XLSX, JSON, TXT (включая экспорт WhatsApp), PDF с текстом, ZIP; вставка текста; много файлов сразу, перетаскиванием.
- Извлекаются: отправитель, получатель, тема, дата, текст, номер заказа (только рядом со словом «zamówienie/order/Bestellung/заказ» или `#12345`), трекинг (UPS `1Z…`, «numer przesyłki…»), идентификаторы переписки (Message-ID, In-Reply-To, References). Отсутствующие данные остаются пустыми — ничего не придумывается.
- **Без дубликатов:** письма с Message-ID узнаются по нему, остальные — по отпечатку (отправитель + дата + тема + текст). Повторный импорт обновляет задачи, а не создаёт новые.
- Ваши заметки, статусы и ручные правки (название, приоритет, клиент и т.д.) при повторном импорте не перезаписываются.
- Если после «Выполнено» или «Ответил» приходит новое письмо клиента, задача автоматически открывается снова.
- Время последнего импорта каждого источника — на главной и на странице импорта. История всех импортов.
- Проверка формата (расширение и сигнатура файла), лимиты размера, защита от «ZIP-бомб», понятные сообщения об ошибках.

**Умная обработка (правила, без внешних сервисов)**
- Автозадачи: «Проверить доставку», «Подготовить этикетку возврата», «Ожидать возврат от клиента», «Обработать возврат», «Подготовить фактуру», «Обработать рекламацию», «Проверить перевозчика», «Ответить клиенту». Ключевые слова на польском, английском, немецком и русском.
- Более точная категория заменяет общую (например, «хочу вернуть» → потом «отправлю сам» = одна задача «Ожидать возврат»).
- Автоприоритет: критический при угрозах (UOKiK, rzecznik, суд, chargeback, негативный отзыв, «pilne/urgent/dringend»), высокий для рекламаций и доставки, +1 уровень, если клиент ждёт больше 48 часов. Любой приоритет можно задать вручную.
- «Возможно, клиент ожидает ответа» — если после последнего сообщения клиента в загруженной истории нет вашего ответа. Формулировка осторожная: если отправленные письма не импортированы, приложение предупреждает, что история может быть неполной.
- «Возможно пропущенные» — переписки, где последнее сообщение от человека (не робота) и нет задачи. Можно отметить «Не требует ответа».
- Группировка по перепискам и заказам (раздел «Сообщения»), глобальный поиск по клиенту, заказу, трекингу, тексту и заметкам.

**Спросить AI**
- Локальный режим (по умолчанию): понимает типовые вопросы — «что самое срочное», «кому я не ответил», «рекламации UPS», «возвраты не поступили на склад», «проблемы с DPD», «найди заказ 123456», «какие фактуры», «что осталось со вчера», «что я выполнил сегодня», «отчёт директору», «напиши ответ на польском по T12», «сообщения клиента …». Каждый ответ со ссылками на задачи [T…] и сообщения [M…]. Если данных нет — так и говорит.
- Режим Claude API: включается, только если задан `ANTHROPIC_API_KEY` **и** в Настройках поставлена галочка разрешения. По умолчанию e-mail, телефоны и IBAN маскируются перед отправкой. Модель отвечает только по переданным данным и со ссылками.
- Черновики ответов клиентам (PL / EN / DE / RU, язык определяется по письму): шаблоны без AI, генерация с AI. Приложение **никогда** не отправляет письма, не оформляет возвраты и не меняет заказы.

**Архив** — JSON / ZIP / CSV / Markdown-отчёт / «Подготовить данные для Claude» (с маскированием персональных данных), сохранение на сервере, восстановление.

**Безопасность** — пароль (APP_PASSWORD), подписанная HttpOnly-cookie с SameSite=Strict, ограничение попыток входа, проверка Origin для изменяющих запросов, запрет запуска в сеть без пароля, заголовки безопасности, ключи только в `.env`, HTTPS через Caddy.

## 9. Миграция на PostgreSQL

Весь доступ к базе — в `src/lib/*` через стандартный SQL. Для перехода: заменить `better-sqlite3` на `pg` в `db.ts`, перевести схему (`INTEGER PRIMARY KEY` → `SERIAL`, FTS5 → `tsvector` + индекс GIN с `unaccent`, `json_each` → `jsonb_array_elements_text`), перенести данные через «Архив → JSON» и восстановление. Формат резервной копии от базы не зависит.

## 10. GDPR и правила компании

- По умолчанию данные клиентов не покидают компьютер/сервер.
- Отправка в Claude API — только с отдельного разрешения в Настройках; включайте её лишь с согласия работодателя и при наличии договора обработки данных (DPA).
- «Данные для Claude» можно сформировать с маскированием e-mail, телефонов и фамилий.
- Демо-данные отделены от настоящих, «Удалить все данные» стирает базу (с предварительной копией).
- Пароли от Gmail/Allegro и т.п. приложение не хранит и не будет хранить — только официальные OAuth-токены на этапе 3.
